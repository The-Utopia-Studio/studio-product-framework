One sentence

Apps orchestrate; packages compose; Effect fences money, inference, and delivery; agents compound the framework.

Built for

Venture teams shipping subscription SaaS, credit-metered AI, and agent-native products without rebuilding plumbing.

Pairs with

Icarus for discovery and commit — SPF holds the build platform, not a second playbook.

Why this exists

Stop rebuilding auth, billing, agents, and observability for every product.

Teams rebuilding the same infrastructure for every AI-native company waste the advantage of agentic shipping. Studio Product Framework is the shared operating system: compose packages, build in apps, let builder agents and humans use the same structure — and keep improving via research, improve, and ship loops without a human owning continuous polish.

Compose, don't fork

  • Apps orchestrate domain rules and policy
  • Packages expose capability blocks with explicit inputs
  • No god services, no package DB writes

Client never touches the database

  • Convex only — auth, validation, rate limits on server
  • Managed backends by default
  • Effect only where bugs cost money or trust

Compound every ship

  • Plan → Work → Review → Compound
  • Research queue → improve-framework loop
  • Handover to operators after 1–2 Studio iterations

Agent OS

Two kinds of agents — builder and runtime

Builder agents live in agents/ and improve the framework. Runtime agents serve end users in sandboxes via @studio/ai-runtime. They must not be conflated.

Builder agents

  • Superpowers + Ponytail for token-efficient codegen
  • Compound engineering loop: Plan → Work → Review → Compound
  • Ship-ready PR, improve-framework, operate-handover loops
  • Hivemind for shared team memory; git remains durable truth

Runtime agents

  • Sandboxed execution for end-user tasks
  • Metered credits and inference brokerage
  • Langfuse on every inference run
  • Web tools: research, scrape, act — with explicit role separation

01 · Commit

score-problem → commit-v1 — venture gate with discovery artifacts before bootstrap.

02 · Build

compound-engineering — ship features with plan, work, review, compound habits.

03 · Improve

research → improve-framework — bounded self-improvement with a file-based queue.

04 · Operate

operate-handover — operators own tweaks after 1–2 Studio feedback iterations.

Quality OS

Reviews and observability are first-class — not bolted on after the fact.

Ship bar

  • Rams — design review on PRs
  • Greptile + greploop — code review loop
  • Aikido — security scanning and AI pentest

Observe

  • PostHog — product analytics and flags

Web decision matrix

  • Parallel — cited research
  • Firecrawl — URL to markdown
  • Browserbase — act in the browser

Quick start

Clone, configure, run.

Install deps, copy env, run Convex dev and the web app. Wire Langfuse and web keys as needed. Install Greptile, Rams, and Aikido on GitHub before you ship.

Open repository Getting started 
pnpm install
cp apps/web/.env.example apps/web/.env.local
# fill Clerk, Convex, billing, PostHog, Sentry, model keys

cd apps/web && npx convex dev   # terminal 1
pnpm dev:web                    # terminal 2  → http://localhost:3000
